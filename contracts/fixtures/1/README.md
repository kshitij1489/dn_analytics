# Contract 1.7 fixtures

Golden request/response payloads for 100% coverage of the `desktop_analytics_app_sync` wire contract.

> **Strict-only (2026-07-09):** the legacy batched ingest endpoints (`POST customer-merges/ingest`, `POST menu-merges/ingest`, `POST menu-mapping-verifications/ingest`) were **removed** and now return `404`. Fixtures for those endpoints are retained as **historical** references to the wire shape the commit path still persists; mutations land through the commit endpoints (§19, §21).

> **Forecasts server-authored only:** `POST forecasts/ingest` (§18.4) is **removed** and returns `404`; its request/response fixtures are gone because no code path persists that shape any more. `GET forecasts/bootstrap` (§18.5) is **also removed in 1.2** and returns `404` — it was a route alias kept because the deployed desktop built that path. `GET forecasts/central-bootstrap` is the only name, returning the §22.6 `runs` / `rows` / `weather_rows` body; the legacy six-array response is gone and `legacy=1` is refused with `400` (`code: retired_parameter`) rather than ignored.

**Contract version:** `1.7` — matches `central_server_analytics_app_api_contract.md` revision `1.7`.

> **Breaking change in 1.1 (§23):** `X-Restaurant-ID` is required on every scoped route — no default restaurant, no `?restaurant_id=` alternative — and the child analytics streams no longer return `order_pk` / `order_item_pk`.
>
> **Breaking change in 1.2 (§24):** the `strict_mode_enabled` response key is gone from every payload; a client `order_line_key` / `petpooja_order_id` / `petpooja_itemid` on an assignment write is a `400 retired_field`; the `legacy` and `scope_key` query parameters are a `400 retired_parameter` on every scoped route; `forecasts/bootstrap` is a `404`; and the §17.6 assignment snapshot no longer filters out the collapsed `menu_item_id`s one desktop release could not map. Fixtures reflect 1.2 only — there is no 1.0 or 1.1 compatibility mode, and none is coming: the desktop is rebuilt against this revision.

> **Additive change in 1.3 (§25):** global menu groups. `GET /analytics/restaurants/` gains the always-present `menu_group_id` / `menu_capabilities` keys, the §17.6 assignment snapshot gains `global_menu_item_id` / `global_variant_id` when a group has linked the row, and `global_menu_fixtures.json` covers the new routes. Nothing is retired and a 1.2 client keeps working: a restaurant in no menu group behaves exactly as before.

> **Breaking global-menu freeze in 1.4 (§25):** the provisional unversioned snapshot/event payloads are replaced by schema-versioned envelopes using `after` / `next_cursor` / `has_more`, a coherent nested snapshot watermark, and complete semantic event deltas with tombstones. Assignment snapshots always carry schema/group metadata. There is one controlled client and capability remains off until it is rebuilt, so no provisional 1.3 global-wire adapter is retained.

> **Global-menu corrections in 1.5 and 1.6 (§25):** the implemented preview/undo/lifecycle/event-scope/backfill behavior is pinned by the global fixtures. No adapter for the earlier provisional global wire is retained.

> **Coordinated shared-Petpooja change in 1.7 (§9, §25):** an optional per-restaurant catalog observation feeds one reviewed group bootstrap; groups explicitly advertising `global_menu_shared_pos_catalog_v1` use group-scoped POS rules with canonical decimal prices, expose a unified read-only history, and refuse restaurant-only canonical writes from shadow onward. The existing mapping rule is the item/variant pair; there is no `GlobalMenuItemVariant` table. Revision 1.7 is frozen for implementation and must not be advertised until both repos pass these fixtures.

**Every §24 code has a fixture, and every fixture is pinned.** `retired_parameter`, `retired_field` and `restaurant_selector_not_a_parameter` each carry a golden body compared against a live response by the server suites (`analytics.tests.Phase4ContractFixtureTests`, `desktop_analytics_app_sync.tests.SyncRestaurantSelectorTests` and `.MenuMutationCommitPhase2Tests`). A published code the server never sends would be the same silent failure the refusals exist to prevent, one level up. `analytics_stream_fixtures.json` and `global_menu_fixtures.json` additionally fail their suites if any fixture in the file has no test pinning it. The §25 refusal and empty-page fixtures are compared byte-for-byte; the data-bearing ones are compared by field *shape*, because global ids are server-issued per install and a value comparison would pin nothing but the test's own random uuids.

**Enablement:** Sync endpoints share `Authorization: Bearer <SYNC_API_KEY>` auth (§4.1) under base path `/desktop-analytics-sync/`. The §23 analytics streams live at `/analytics/` and authenticate with `X-API-Key`. Both require `X-Restaurant-ID` on every scoped route.
